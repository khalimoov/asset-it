УЧЁТ ИТ-ОТДЕЛА — УСТАНОВКА В DOCKER (Linux)
===========================================

Пакет asset-it-docker.zip ставит приложение двумя контейнерами:
  app  — сервер приложения (Python, waitress, Tesseract для накладных)
  db   — PostgreSQL 16, данные в томе pgdata

Архив накладных лежит на диске сервера в папке  /opt/asset-it/documents
и монтируется в контейнер по тому же пути. Контейнеры можно пересоздавать —
документы и база от этого не пропадают.


ЧТО ДОЛЖНО БЫТЬ НА СЕРВЕРЕ
--------------------------

  * Linux (Ubuntu 22.04/24.04, Debian 12 и т. п.)
  * Docker с плагином compose:   docker --version   и   docker compose version
    Установка на Ubuntu:  curl -fsSL https://get.docker.com | sh
  * Интернет на время сборки образа: докачиваются python:3.13-slim,
    postgres:16, пакеты Debian (tesseract) и библиотеки Python.
    После сборки интернет не нужен.

    Если на сервере интернета нет вовсе — используйте офлайн-пакет:
    на любой машине с Docker и интернетом выполните из этой папки
        sh build-offline.sh --debs noble      (noble — Ubuntu 24.04,
                                               jammy — 22.04, bookworm — Debian 12)
    и отвезите на сервер dist/asset-it-docker-offline.tar.gz.
    Дальше — по offline/УСТАНОВКА-OFFLINE.txt (он же внутри архива).


УСТАНОВКА
---------

  1. Распакуйте архив, например в /opt/asset-it:

       sudo mkdir -p /opt/asset-it
       sudo unzip asset-it-docker.zip -d /opt/asset-it
       cd /opt/asset-it/asset-it-docker

  2. Папка для документов:

       sudo mkdir -p /opt/asset-it/documents

  3. Настройки — скопируйте образец и впишите пароль базы:

       cp .env.example .env
       nano .env            # PGPASSWORD=любой_придуманный_пароль

     Пароль нужен только контейнерам между собой. Порт (PORT) и часовой
     пояс (TZ) можно оставить как есть.

  4. Сборка и запуск:

       docker compose up -d --build

     Первый запуск собирает образ 2–5 минут. Дальше проверяем:

       docker compose ps                 # оба контейнера в состоянии running/healthy
       docker compose logs app           # если что-то пошло не так — причина здесь

  5. Первый вход. Откройте  http://адрес-сервера:8000 — пока в базе нет ни
     одной учётной записи, страница показывает экран первого запуска:
     впишите имя, придумайте логин и пароль. Это и будет администратор.
     Остальных пользователей он заводит в разделе «Пользователи ИТ».

     Забыли пароль администратора — задайте новый с консоли:
       docker compose exec app python server/reset_password.py <логин>


ОБНОВЛЕНИЕ НА НОВУЮ ВЕРСИЮ
--------------------------

  Распакуйте новый архив поверх старого (файл .env остаётся ваш) и:

       docker compose up -d --build

  Схема базы доводится до актуальной сама при старте (миграции идемпотентны).
  Данные и документы не трогаются.


РЕЗЕРВНЫЕ КОПИИ
---------------

  База (файл лучше складывать на другой диск):

       docker compose exec -T db pg_dump -U asset_it -F c asset_it > asset-it-$(date +%F).dump

  Восстановление в пустую базу:

       docker compose exec -T db pg_restore -U asset_it -d asset_it -c < asset-it-2026-09-21.dump

  Документы — просто копия папки /opt/asset-it/documents.


ПОВСЕДНЕВНОЕ
------------

  остановить            docker compose stop
  запустить             docker compose start
  перезапустить app     docker compose restart app
  журнал в живую        docker compose logs -f app
  снести контейнеры     docker compose down          (том pgdata и документы остаются)
  снести вместе с базой docker compose down -v       (БЕЗВОЗВРАТНО удаляет базу)

  Контейнеры перезапускаются сами после перезагрузки сервера
  (restart: unless-stopped), отдельный автозапуск не нужен.


НАСТРОЙКИ, КОТОРЫЕ СТОИТ ЗНАТЬ
------------------------------

  * Папка архива в интерфейсе («Приходные накладные» -> «Куда сохранять»)
    по умолчанию /opt/asset-it/documents. Если поменять на другую, она
    должна быть смонтирована в контейнер — иначе файлы останутся внутри
    контейнера и пропадут при пересоздании. Правильный способ сменить папку:
    поправить строку volumes в docker-compose.yml.

  * Опрос сети (раздел «IP-адреса») работает из контейнера: ping и стук
    в порты 445/3389 идут через сеть Docker. Если адреса не отвечают, хотя
    машины в сети, попробуйте режим сети хоста — в docker-compose.yml у app
    заменить блок ports на  network_mode: host  (тогда порт 8000 берётся
    напрямую с сервера).

  * Вход через Active Directory и загрузка сотрудников — как в обычной
    установке, контроллер домена должен быть доступен с сервера по LDAP.

  * Распознавание: словари rus и eng ставятся из пакетов Debian при сборке
    образа, в разделе «Приходные накладные» состояние показывает
    «Распознавание готово: tesseract 5.x».
